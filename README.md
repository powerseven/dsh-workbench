# dsh-workbench

个人工作台 —— DeepSeek Harness（dsh）Web 插件。管四件事：
**待办 · 计划 · 委派 · 分级拆解**，用**重要程度**决定该管多严，附版本留档。

不是独立应用：它作为侧边栏的一个 tab 跑在你的 `dsh web` 里。

## 它解决什么

普通待办应用里，**进度要人来同步**——你干完一件事，得自己去勾掉。
在 dsh 里这件事可以反过来：插件把计划暴露成一组 agent 工具，
**AI 干完活自己把任务标完成，完成度自动重算**。

所以这个插件的设计原则是：任何能力都问一遍「agent 能不能也做」，
能就让工具和 UI 共用同一份数据。

## 核心概念

```
📥 收件箱       不挂任何计划的游离待办——先记下来，之后再归位
计划 n1   Q4 数据治理专项            40%     负责人 张三 · 2026-10-01 ~ 12-31
├─ 计划 n2   完成 12 个台区改造       25%     3/12 个
│  ├─ 待办 n5  台区 A 改造
│  └─ 待办 n6  台区 B 改造
└─ 计划 n3   建立治理台账             33%
   ├─ [x] n7  收集基础数据
   ├─ [ ] n8  录入系统               截止 2026-11-01   张三 · 待接受
   └─ [ ] n9  复核
```

**计划可以一直往下分**——年度拆季度、季度拆月度、月度拆周。层级不设限，
每一层都是同一个节点模型，**随手记的待办可以随时原地提升为计划继续拆**。
收件箱里的待办不属于任何计划。

**重要程度不是彩色标签，而是管控强度开关**：

| 重要程度 | 会发生什么 |
|---|---|
| 高 | 计划必须有周期与负责人、待办必须有截止；缺口会被标出来 |
| 中（默认） | 要有截止；到期提醒 |
| 低 | 只记录，不催 |

它解决通用待办工具的通病——所有事走同一流程，结果大事没人盯、小事太吵。

**委派带回执**：记录对象、委派时间、期望完成时间，状态分
待接受 / 已接受 / 已拒绝 / 已交回。逾期分两种：**未回执**（该去问一句）
与**未完成**（该去催）。委派如果没有回执，就等于交代完石沉大海。

计划节点的进度**递归算出**，自动识别两种度量：
- **量化**：声明 `target`/`current`，按比例算（如 `3/12 个`）
- **清单**：有子节点就取子节点平均；叶子待办按状态（完成 = 100%）

全计划完成度 = 各个顶层计划平均（收件箱不计入——
它不是计划的一部分，但会计入角标与筛选）。

## 数据在哪

落在**当前会话的工作区**里，跟着你的项目走、能进 git：

```
<workspace>/plan/plan.json      结构化真相
<workspace>/plan/PLAN.md        自动生成的只读视图（可读、可 diff）
<workspace>/plan/.versions/     每次变更前的快照
```

版本留档**独立于 git**：即使这个目录没被 commit，或你根本不用 git，
`plan/.versions/` 里依然有完整演进，可以回滚。

> `PLAN.md` 是生成物，别手工编辑——下次写入会覆盖。要改计划就让 agent 改，
> 或直接改 `plan.json`（结构变了 `PLAN.md` 会在下次写入时重新生成）。

## 安装

```sh
node scripts/build.mjs
dsh plugin --profile web add /Users/tinyseven/Documents/DSH/dsh-workbench
```

**装完必须重启 `dsh web`** —— host 插件是组合树里的一行，不是热加载。

卸载：

```sh
dsh plugin --profile web remove dsh-workbench
```

## 用法

### 记一条待办（成本趋近于零）

在侧边栏面板顶部的输入框敲一句、回车 —— 落到**收件箱**。
还不知道该归到哪个计划下时就这么用；之后归位到子计划下即可。

### 让 agent 建计划

在任意会话里说：

> 帮我把这个季度的工作计划拆成计划和子计划，写到这个工作区的计划里

agent 会调 `plan_node_add` 逐层落成计划树——想拆几层就拆几层。

### 分级拆解

层级不设限。对 agent 说「把『建立治理台账』再拆成三步」，
agent 就在该计划下继续挂子节点。面板上每个计划节点旁的「＋」可以直接加子节点，
「↳」把节点移动到别的计划下——收件箱里那些当初随手记的待办，就是这么归位的。

记的时候不用先想清楚它该是计划还是待办：**待办旁边的「⇧」能把它提升为计划**，
之后再往下拆；空计划旁边的「⇩」能降回待办。换型是原地改，id 不变。

### 委派出去并跟住

> 把「建立治理台账」委派给张三，周五前给我

agent 调 `plan_delegate_set` 建委派；之后张三接了活说一句「张三接单了」，
agent 调 `plan_delegate_receipt` 记回执。问「我委派出去了哪些事」可看
`plan_delegated`（逾期的排在最前面），面板上也有「我委派出去的」筛选。

### 标重要程度

对 agent 说「把 Q4 数据治理专项标成高重要度」，或在面板上点标题旁边的
「高/中/低」徽章循环切换。标成「高」之后如果还缺周期或负责人，
工具返回的 `warnings` 与面板上的 ⚠ 会指出来。

### agent 回写进度

> 台区 B 的方案评审做完了

agent 调 `plan_todo_set` 把 `n8` 标成 `done`，**顺带记下完成时间**，
完成度自动重算——你不需要动手同步。

### 侧边栏面板

侧边栏顶部「+」菜单里添加「🎯 工作计划」tab。面板里可以直接：

- 记待办进收件箱（顶部输入框）
- 勾选待办（立即回写 `plan.json`）
- 给计划节点加子节点（「＋」选待办或子计划）
- 换型：待办「⇧」提升为计划，空计划「⇩」降回待办
- 移动节点到别的计划下 / 移回收件箱（「↳」选择目标）
- 删除节点（「×」，带确认；子节点一并删除）
- 点徽章改重要程度
- 看委派对象与回执状态（逾期标红，鼠标悬停看详情）
- 用筛选条看「重要度高 / 我委派出去的 / 本周到期 / 逾期」
- tab 角标显示未完成事项数

### 手动留档 / 回滚

对 agent 说「给当前计划留个档」，或直接调 `plan_snapshot`；
`plan_history` 看历史版本，`plan_restore` 回滚。
每次通过工具或面板修改计划前都会自动留档，所以回滚本身也可撤销。

## 工具一览（13 个）

工具面按**节点**组织，不按层级——只有 4 个结构操作作用在任意节点上，
`type` 决定它是计划还是待办。原来按「目标 / KR / 任务」分三套 API 是固定三层的
产物：三套做同一件事，agent 每次还得先想「这算目标还是 KR」。

| 工具 | 作用 |
|---|---|
| `plan_show` | 查看计划树（含进度、管控汇总、委派清单） |
| `plan_node_add` | 加节点：计划或待办，`parent` 指父计划，不传就进收件箱 |
| `plan_node_set` | 改任意节点的标题 / **类型** / 负责人 / 周期 / 截止 / 重要程度 / 状态 / 量化进度 |
| `plan_node_move` | 归位或调序（移到别的计划下、移回收件箱） |
| `plan_node_remove` | 删节点（计划会连同子项一起删） |
| `plan_todo_set` | 改待办状态（自动记完成时间） |
| `plan_priority_set` | 设置任意节点的重要程度（返回还缺什么） |
| `plan_delegate_set` / `plan_delegate_receipt` | 建立委派 / 登记回执 |
| `plan_delegated` | 列出「我委派出去的」（逾期在前） |
| `plan_snapshot` | 手动留档一个版本 |
| `plan_history` / `plan_restore` | 版本列表 / 回滚 |

定位节点时 id 和标题都能用（`n1`、`建立治理台账`），有歧义时会报错而不是猜。
`plan_node_set` 改 `type` 可以把待办提升成计划继续拆——有子节点的计划不能降级为待办。
