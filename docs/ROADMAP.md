## v0.1.0

已交付：三级计划树、两种 KR 度量（量化 / 清单）、自动进度汇总、
agent 工具集（10 个）、侧边栏面板、版本自动归档与回滚。

## v0.2.0

按 [PRD](./PRD.md) 的 MVP 第一步交付，**不破坏原有数据结构**：

- **收件箱**：顶层待办承载不挂任何计划的待办；面板顶部可一句话记入。
- **重要程度**：`priority` 三档，是**管控强度开关**——高要求周期与负责人、
  中要求截止、低不打扰；缺口由 `nodeWarnings` 提示而不拦下。
- **委派**：`delegate` 带四种回执状态与期望完成时间；两种逾期分开标记
  （该去问 vs 该去催），并有「我委派出去的」视图。
- **完成时间戳**：`doneAt` / `startedAt`，离开完成态会清掉 `doneAt`。
- 工具面 10 → 15 个；HTTP 数据面 5 → 7 条；测试 54 → 133 个。

## v0.3.0

MVP 第二步：**固定三层 → 递归节点树**（破坏性变更，单独分支 + PR）。

- **递归树**：`plan.nodes[]`，`node.type = plan | todo`，`children` 深度不限。
  三层只是它的特例——「年度 → 季度 → 月度 → 周 → 待办」这类链条现在放得下。
- **老数据自动迁移**：读取时迁移、写入时落新格式；老 id（`g1`/`k1`/`t1`）原样保留
  （历史会话与 `.versions/` 快照仍引用它们），新节点统一 `n` 前缀。用户不需要
  跑任何迁移脚本，也不会有哪一刻看到坏数据。
- **工具面收敛**：`goal/kr/task` 六件套 → 节点模型四件（add / set / move / remove）。
  三套 API 做同一件事，agent 每次都得先判断「这东西算 goal 还是 kr」。
- **补上两处缺口**：收件箱归位（把游离待办移进计划）与节点删除（此前完全没有）。
- **换型**：`plan_node_set` 加 `type`——随手记的待办能原地提升为计划继续拆，
  空计划能降回待办。待办是叶子，所以有子节点的计划不允许降级；
  跨类型时状态会重新归一（`active` 只对计划合法），避免留下对该类型非法的状态。
  （**后于 v0.5.0 移除**：类型改为由结构派生，见下节。）
- 工具面 15 → 13 个；HTTP 数据面 7 → 9 条；测试 133 → 170 个。

## v0.4.0

MVP 第三步：**兑现「高」的承诺**。重要程度一直是「管控强度开关」，
但之前只有两条警告在生效——标签是真的、开关还是纸的。这一版把它补实。

- **落后预警**（FR-M5）：有完整周期的计划，按 `(今天 − start) / (end − start)`
  与 `nodeProgress` 比，差 ≥ **15 个百分点**标为落后。15% 而不是「落后就报」，
  是因为刚开工时落后是正常状态，报出来只会让人开始忽略这个标记。
  四种情况不报：没周期 / `start` 还没到 / 已过 `end`（那是**逾期**，
  两种信号触发不同动作）/ 已完成或已放弃。**待办不讲配速**——待办没有周期，
  它的落后表现就是逾期。
- **完成证据**（FR-A3）：`evidence: [{ kind, ref, note?, at }]`，**追加式**；
  `kind` 固定五种（file / session / command / link / note），缺省 note；
  同 kind + 同 ref 不重复追加；只有 `file` 会被核验（文件是否存在）。
  **不强制**：硬拦只会诱使 agent 编一条假证据，那比没有更糟——
  改成「无证据的完成项进清单 + 面板 `⊘` + 一个筛选」，让「AI 说它干完了」
  可被一次性审查。
- **不加工具、不加路由**：落后预警是读时算出来的派生量，证据是两个写入工具上的
  可选标量参数。工具 13 个、路由 9 条不变——**这正是这一版的设计目标**。
- 顺带修掉一个真 bug：`applyFields` 曾经整体替换 `metric`，「只更新当前值」
  会把 `target` 静默抹掉（进度从「10/12」悄悄变成按状态算）。现在逐字段合并。
- 测试 170 → 213 个。

## v0.5.0

MVP 第四步：**把面板补成可以徒手用**。此前面板能勾选、能点徽章、能加子项，
但最常用的两个动作——改名和调整顺序——都得回到对话里让 agent 做。
这一版把它们拿回面板；**host 半身一行没改**，全部复用已有的 `/node-set` 与 `/node-move`。

- **双击改名**：双击标题就地编辑，回车提交、Esc 取消、失焦提交；
  标题没变或清空则不落盘。写路径仍走 `/api/workbench/*` → `store.js`（含版本归档），
  版本留档因此不留盲区。
- **拖拽排序与改挂载**：把节点拖到另一个节点上，按落点分三档——
  上半区插到它前面、下半区插到它后面、中间落进它里面（叶子节点没有「里面」，
  自动降级为前后插入）。拖到空白处 = 移到顶层末尾；
  拖到自己的子树里、或原地不动，都会被拒（不写盘、不产生空版本）。
- **折叠展开**：树能拆到任意深，节点一多就必须能收起来。
  折叠状态存 **localStorage 而不是 `plan.json`**——它是这台机器的显示偏好，
  不是计划数据；写进 JSON 会污染 diff、进版本快照、还会跟着 git 同步到别人机器上。
  计划下有子节点才显示折叠标记；表头在 `depth ≥ 2` 时出现「全部折叠 / 全部展开」。
- **新建顶层计划**：空收件箱时给一个入口，否则面板没有第一下手的地方。
- **不加工具、不加路由**：工具 13 个、路由 9 条不变，复用 `/node-set`（改名）
  与 `/node-move`（带 `index` 的排序）——**这一版的设计目标就是「不加能力面、只补手势」**。
- **新增第 5 层测试 `test/client.test.mjs`**：用假 React（5 个 hook 按调用序还原）
  驱动**真实构建产物**里的面板组件，能验到「双击→发请求→重渲染」这条端到端链路，
  补上了纯函数测试与产物断言都覆盖不到的中间层。
- 测试 213 → 247 个。

## 下一步候选

### 1. 让 agent 主动（V1 的其余项）

一句话拆解目标（FR-A5）· 委派验收（FR-D3，同意 / 打回）· 周期复盘（FR-R3）。
共同点是「从能读写升级到会判断」——递归树建好之后，「一句话拆成多层」才真正可用。
落后项与逾期委派的清单已经就位，缺的是 agent 主动播报的时机（会话开头扫一遍）。

### 2. 周报文档自动生成（FR-R1）

**前置依赖已全部解除**（`doneAt` + `evidence`）。方向仍是做成 **skill 而不是插件**
——产出物是文档（docx/邮件），形态每次都不同。数据源现成：完成项有 `doneAt` 与证据，
落后项有 `behind` 清单，委派有回执，递归树还让「按子计划分段汇报」变得自然。
面板里的日报 / 周报**视图**已经做好，但那是给人主动去看的读法，不等于这一项。
（注：这一步被明确跳过过一次，登记在此以备后选。）

### ~~3. 看板 / 甘特 / 日历视图~~ —— 作废

**看板那半条已被推翻**：看板视图做过（按顶层计划分列），后来被**报告视图替换**
（不是并列成第四档），理由是树 / 看板 / 执行清单回答的都是「现在有什么」，
只有按时间切片才回答得了「这一期发生了什么」。当前三档是
工作计划 / 当前任务 / 报告，没有看板，也不再作为下一步候选。
**甘特 / 日历那半条仍然有效**：甘特需要待办有起止日期（当前只有 `due`，
数据模型要先扩）；日历先确认是否与 `magicOF2/dsh-schedule` 重叠。

### 4. 权重 + 置信度

OKR 工具标配。权重只是让进度汇总换个算法；置信度更值得先做——
它携带的是「人的判断」，机器算不出来，而 agent 预警正需要它。
详见 [FEATURES.md 优先级建议](./FEATURES.md#七优先级建议)。

## 有意不做的部分

### 接单 / 续跑（AI 自动执行的后半段）

`dsh-task-panel` 已经做了「发布任务 → 子 agent 串行执行 → 自动复核 → 待验收」，
`dsh-todo-board` 做了「三档执行模式（提醒／当前会话续跑／自动新开会话）」。
这两个都比重新实现更成熟，而且它们管的是**会话调度**，与本插件管的
**计划数据**是两件事。

正确做法是**分工而非重叠**：本插件专注计划的编辑与跟踪（数据层），
执行调度交给它们。若要联动，让本插件的任务能被派发出去即可，
而不是自己造一套调度器。

### JSON 之外的第二真相源

不要为了「方便手改」而让 `PLAN.md` 变成可写。详见
[DESIGN.md](./DESIGN.md#数据模型为什么-json-是真相markdown-是视图)。

## 技术债

- `src/index.js` 里 15 个工具的参数定义与 `store.js` 的字段校验有重复，
  字段增删要改两处。规模再大就该抽一层 schema。
- **工具参数 schema 无法表达 `null`**（见 [AGENTS.md 坑 #8](../AGENTS.md)），
  「移到顶层」只能用省略参数表达。若将来出现更多「清空某字段」的语义，
  值得引一层自定义转换。
- **跨半身的重复映射**：`nextPriority`、`FILTERS`、`EVIDENCE_KINDS`、
  `progressOf` / `nodeProgress` 之类在 host（ESM）与 client（CJS）各有一份——
  模块系统不同，无法共享。目前用 `test/logic.test.mjs` 的断言把两侧绑住，
  但这只是护栏，不是消除重复。
- `withProgress()` 递归给每个节点挂派生字段（type / progress / priority / warnings /
  delegateState / overdue / dueSoon / pace / behind / unverified / evidenceWarnings），
  读接口的 payload 随节点数线性增长，递归树会让它更容易变大。计划小，暂可接受；
  列表变大后应改成按需计算。
- ~~**`evidence` 只能追加，没有更正入口**~~ **已解**：附错一条可以删掉那一条
  （工具与面板都有删除入口，走 `removeEvidence`；`files` 同理走 `removeFile`）。
  剩下的缺口是**修改**——只能删了重加，仍需先解决「工具参数 schema 表达不了 `null`」
  （坑 #8）才能表达「把这条的 ref 改成新值」。
- **「清空字段」只覆盖了一半**：`applyFields` 只写不删，所以现在分成两条路——
  面板表单额外提交 `clear: string[]` 由 `clearFields` 执行（白名单 `store.CLEARABLE`：
  owner / start / end / due / note / metric / delegate），**工具面没有**。
  「计划不需要量化了」这类诉求，agent 目前只能用空值变通。
- **移动与删除没有「撤销」**：每次写入都归档、可回滚，但那要绕到版本历史。
  删除已有二次确认；若误删代价变大，应考虑把最近一次操作做成可撤销。
- 客户端面板没有做乐观更新，勾选后要等一次往返。计划小，暂可接受。
- 面板未处理 `betterSidebar` 之外的其他宿主（如 `AKS1st/dock` 的
  `ctx.workbench` 注册表）。目前只挂 better-sidebar。
