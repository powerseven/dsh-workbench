## v0.2.0（当前）

按 [PRD](./PRD.md) 的 MVP 第一步交付，**不破坏原有数据结构**：

- **收件箱**：`plan.inbox[]` 承载不挂任何计划的待办；面板顶部可一句话记入。
- **重要程度**：`priority` 三档，是**管控强度开关**——高要求周期与负责人、
  中要求截止、低不打扰；缺口由 `nodeWarnings` 提示而不拦下。
- **委派**：`delegate` 带四种回执状态与期望完成时间；两种逾期分开标记
  （该去问 vs 该去催），并有「我委派出去的」视图。
- **完成时间戳**：`doneAt` / `startedAt`，离开完成态会清掉 `doneAt`。
- 工具面 10 → 15 个；HTTP 数据面 5 → 7 条；测试 54 → 133 个
  （新增 `test/host.test.mjs`：真跑工具与路由的集成测试）。

## 下一步候选

### 1. 第二步：递归节点树（分级做到任意深度）

当前固定三层表达不了「年度 → 季度 → 月度 → 周 → 待办」这种真实链条，
也放不下「子计划嵌子计划」。改成 `type = plan | todo` 的递归树后，深度不限，
而现有三层只是它的一个特例。老 `plan.json` 可机械迁移
（`goal → plan`、`kr → plan(子计划)`、`task → todo`），但属破坏性变更，
**需单独分支 + PR**，并同步改工具面、面板与测试。

### 2. 日报 / 周报自动生成

**缺口最大，且前置依赖已解除**（`doneAt` 已就位）。方向：做成 **skill 而不是插件**
——产出物是文档（docx/邮件），形态每次都不同，用插件硬编码不如让 agent 读计划后
自己生成。数据源现成。

### 3. 面板就地编辑

现在能勾选、能点徽章改重要程度；还缺双击改名、行内「+」加子项、拖拽排序。
写路径必须继续走 `/api/workbench/*` 落到同一套 `store.js`（含版本归档），
不要在前端另写一套——那会让版本留档出现盲区。

### 4. V1 的其余项（agent 接管跟进）

完成需附证据（FR-A3）· agent 主动预警落后项与逾期委派（FR-A4）·
一句话拆解目标（FR-A5）· 委派验收（FR-D3）· 周期复盘（FR-R3）。

### 5. 看板 / 甘特 / 日历视图

同一份数据的另外三种投影。看板成本最低；甘特需要任务有起止日期（当前只有
`due`，数据模型要先扩）；日历先确认是否与 `magicOF2/dsh-schedule` 重叠。
建议先做看板，观察是否真的比树形好用。

## 有意不做的部分

### 接单 / 续跑（AI 自动执行的后半段）

`dsh-task-panel` 已经做了「发布任务 → 子 agent 串行执行 → 自动复核 → 待验收」，
`dsh-todo-board` 做了「三档执行模式（提醒／当前会话续跑／自动新开会话）」。
这两个都比重新实现更成熟，而且它们管的是**会话调度**，与本插件管的
**计划数据**是两件事。

正确做法是**分工而非重叠**：本插件专注计划的编辑与跟踪（数据层），
执行调度交给它们。若要联动，让本插件的任务能被派发出去即可，
而不是自己造一套调度器。

### JSON 之外的第二真相源

不要为了「方便手改」而让 `PLAN.md` 变成可写。详见
[DESIGN.md](./DESIGN.md#数据模型为什么-json-是真相markdown-是视图)。

## 技术债

- `src/index.js` 里 15 个工具的参数定义与 `store.js` 的字段校验有重复，
  字段增删要改两处。规模再大就该抽一层 schema。
- **跨半身的重复映射**：`nextPriority`、`FILTERS` 之类在 host（ESM）与 client（CJS）
  各有一份——模块系统不同，无法共享。目前用 `test/logic.test.mjs` 的断言把两侧绑住，
  但这只是护栏，不是消除重复。
- `withProgress()` 给每个节点挂 4 个派生字段（priority / warnings / delegateState /
  overdue），读接口的 payload 会随计划规模线性增长。计划小，暂可接受；
  若将来列表变大，应改成按需计算。
- **收件箱只能进、不能「归位」**：把游离待办移进某个子计划的操作还没有（FR-C4，P1）。
  现在只能新建一次、由 agent 重新建。
- 客户端面板没有做乐观更新，勾选后要等一次往返。计划小，暂可接受。
- 面板未处理 `betterSidebar` 之外的其他宿主（如 `AKS1st/dock` 的
  `ctx.workbench` 注册表）。目前只挂 better-sidebar。
