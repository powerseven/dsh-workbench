## 0. 一句话

给**一个人**用的工作计划台：把散在脑子、聊天记录和会议里的**待办**收进来，
按**计划 → 子计划**组织，能**委派**出去并跟踪，用**重要程度**决定该管多严，
让 AI 替你更新进度、写周报。

## 1. 需求提取：从原话到需求

需求方不是产品经理，原话是零散的。下表把原话映射成可执行的需求——这是本方案的地基。

### 显性需求（你说过的）

| 原话 | 提炼出的需求 | 编号 |
|---|---|---|
| 「主要是作为个人工作计划管理」 | 单人使用，不是团队协作工具 | G-1 |
| 「可以从待办…做成」 | 待办是基本单元，且能独立存在 | FR-C1 |
| 「工作计划、子计划」 | 计划可嵌套，层级不限 | FR-P1 |
| 「可以分级」 | 层级深度本身就是级别，不另造体系 | FR-P2 |
| 「委派」 | 事项可交给他人，并且要跟得住 | FR-D1 |
| 「分重要程度管控」 | 重要程度决定流程繁简，**不是标签** | FR-M1 |
| 「AI 能主动更新你的计划进度」 | agent 必须能读写计划，且这是核心价值 | FR-A1 |
| （既有）计划版本留档 | 每次变更前留快照，可回滚 | FR-H1 |
| （既有）工作区有周报/docx 链路 | 要能自动出周报 | FR-R1 |

### 隐性需求（你没直说，但逻辑上必需）

| 隐性需求 | 为什么必需 |
|---|---|
| **委派要有回执与验收** | 只有「指派给谁」字段的委派是假委派——交代完就石沉大海，等于没做 |
| **任务要有完成时间** | 没有时间戳，「本周做了什么」永远回答不了，周报只能靠回忆 |
| **计划要能跨会话保留** | 一次会话做完就散，就不叫计划 |
| **数据要能被人读懂、能带走** | 工具会换，计划不能锁死在工具里 |
| **面板与 agent 必须改同一份数据** | 两套真相源必然漂移，而漂移是最难查的一类 bug |

### 明确不做（非目标）

团队协作与权限角色 · 跨部门目标对齐（级联/对齐矩阵）· 绩效挂钩 · 工作量均衡 ·
日历与自动排程（那是 Motion/Sunsama 的战场）· 甘特图 · 工时计费 · 移动端离线。

一句话：**保留「计划」与「跟踪」，砍掉「组织」与「协作」。**

## 2. 问题定义

**现状**：待办散落在聊天记录、微信、会议纪要、便签里；计划写在文档里，写完就没人看；
委派出去的事没有回音；周报靠回忆拼。

### 三个核心问题

1. **收不进来** —— 事情发生的地方（对话、会议）和记录的地方不是同一处，靠手动誊抄必然漏。
2. **跟不上** —— 计划是静态文档，没有推进机制，做完即烂尾。
3. **管不对** —— 所有事走同一个流程：大事没人盯、小事太吵，最后整个清单失去可信度。

### 目标

- 让「记下来」的成本趋近于零
- 让「跟进度」由 AI 承担，而不是靠人的自律
- 让「管多严」与「多重要」匹配

## 3. 用户与场景

**用户画像**：一个人，在 DSH 里干活。有周期性产出（周报）、有需要委派给同事的事、
有按季度/月度组织的计划，愿意把 AI 当协作者而不是工具。

### 场景故事线（一周）

| 时点 | 发生了什么 | 系统该做什么 |
|---|---|---|
| 周一早 | 「把上周遗留和我这周要交的理一下」 | 读计划，列出逾期项与本周到期项；我把其中两件标成「高」 |
| 周三 | 同事在群里让我整理一份数据 | 记一条待办挂到「Q4 计划」下，标「中」，截止周五 |
| 周三下午 | 领导让我牵头做一件事 | 建一个子计划，委派给张三，写清期望完成时间 |
| 周四 | agent 干完一件事 | 自己把对应待办标完成，并附上产出的文件路径 |
| 周五下班前 | 「出个周报」 | 从计划里取本周完成/进行/风险，生成 docx |
| 周日 | 系统提醒 | 有一条委派给张三的事项逾期未回执，我去问一下 |

### 关键场景清单

| 编号 | 场景 | 成功标准 |
|---|---|---|
| SC-1 | 对话里说一句话，事项落库并挂到正确位置 | 不需要手动打开任何界面 |
| SC-2 | 把一个计划拆成子计划与待办 | 层级不限，缩进即层级 |
| SC-3 | 把一件事委派给张三并设期望完成时间 | 能看到「我委派出去的」列表与逾期委派 |
| SC-4 | 标记重要程度，看到它真的改变了行为 | 高优先级的会被预警、被催、要证据 |
| SC-5 | agent 干完活自己打勾并附证据 | 完成后能查到「谁、何时、凭什么完成的」 |
| SC-6 | 一句话生成周报 | 内容来自计划数据，不靠回忆 |
| SC-7 | 一键回到三天前的计划 | 版本留档可见、可回滚 |

## 4. 功能需求

优先级：**P0 = MVP 必须上线**，P1 = 第二期，P2 = 以后再说。

### M1 捕获（待办）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-C1 | 待办可**独立存在**（不挂任何计划），构成收件箱 | P0 |
| FR-C2 | 可通过对话创建，agent 自动判断该挂到哪个计划下 | P0 |
| FR-C3 | 字段：标题、状态、截止、备注、重要程度 | P0 |
| FR-C4 | 收件箱批量整理（把游离待办归位） | P1 |

### M2 计划与分级

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-P1 | 计划可嵌套子计划，**深度不限** | P0 |
| FR-P2 | 缩进即层级，不强制用户先定义层级名称 | P0 |
| FR-P3 | 字段：标题、周期（起止）、负责人、状态、重要程度 | P0 |
| FR-P4 | 进度 = 其下所有节点进度的汇总（**派生量，不落盘**） | P0 |
| FR-P5 | 折叠/展开，默认只展开高优先级与未完成的 | P1 |
| FR-P6 | 计划模板（「周报流程」「月度对账」等） | P2 |

### M3 委派

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-D1 | 任意节点可委派给某人，记录对象、委派时间、期望完成时间 | P0 |
| FR-D2 | 委派有**回执**：待接受 / 已接受 / 已拒绝 / 已交回 | P0 |
| FR-D3 | 委派有**验收**：完成后由我方确认（同意 / 打回） | P1 |
| FR-D4 | 「我委派出去的」独立视图，含逾期委派提醒 | P0 |
| FR-D5 | 委派对象可扩展到 agent（把事项派给 AI 执行） | P2 |

### M4 重要程度与管控（本产品的核心机制）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-M1 | 三档重要程度，**决定管控强度**而非仅作标签 | P0 |
| FR-M2 | 高：强制周期与负责人；进度需定期更新；落后预警；完成需证据 | P0 |
| FR-M3 | 中：需有截止；到期提醒；完成需证据 | P1 |
| FR-M4 | 低：只记录，不提醒不催 | P0 |
| FR-M5 | 落后判定：按周期已过时间比例 vs 实际进度，落后即标记 | P1 |

### M5 进度与视图

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-V1 | 树形视图：层级 + 进度条 + 重要程度 + 委派对象 + 截止 | P0 |
| FR-V2 | 勾选完成直接回写（面板与 agent 改同一份数据） | P0 |
| FR-V3 | 筛选：高优先级 / 我委派出去的 / 本周到期 / 逾期 | P0 |
| FR-V4 | 就地编辑（改名、加子项、排序），不必每次都找 agent | P1 |
| FR-V5 | 看板视图（按状态分列） | P2 |

### M6 复盘与报告

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-R2 | **完成时间戳 `doneAt`**，支撑所有时间维度统计 | **P0** |
| FR-R1 | 一句话生成周报/月报（完成项 / 进行项 / 风险项 / 下周重点） | P1 |
| FR-R3 | 周期复盘：agent 扫计划 + 会话，起草「进展 / 卡点 / 调整」 | P1 |
| FR-R4 | 统计：本周完成数、逾期分布、委派回执率 | P2 |

### M7 agent 能力（差异化核心）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-A1 | agent 可读全量计划 | P0 |
| FR-A2 | agent 可增删改节点、改状态、回写进度 | P0 |
| FR-A3 | agent 标记完成时**必须附证据**（文件路径 / 会话 id / 命令输出） | P1 |
| FR-A4 | agent 主动预警：落后项、逾期委派、长期未动的节点 | P1 |
| FR-A5 | agent 主动拆解：把一句话目标拆成计划 + 子计划 + 待办草稿 | P1 |

### M8 留档与数据主权

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-H1 | 每次变更前自动快照，可列可回滚 | ✅ 已有 |
| FR-H2 | 计划为工作区内可读文件（JSON 真相 + Markdown 视图） | ✅ 已有 |
| FR-H3 | 本地私有，不进共享仓库 | ✅ 已有 |

## 5. 非功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-1 | **写入路径唯一** | 面板、agent、HTTP 面共用同一套存储逻辑（含版本归档），不许前端另写一套 |
| NFR-2 | **进度是派生量** | 不落盘，避免两个真相源漂移 |
| NFR-3 | **向后兼容** | 新增字段一律可选，缺省行为与现状一致，不回填历史数据 |
| NFR-4 | **可回滚** | 任何变更前有快照，回滚本身也可撤销 |
| NFR-5 | **数据可携带** | JSON + Markdown，随时能读、能迁移 |
| NFR-6 | **隐私** | 计划是个人工作数据，本地私有 |

## 7. 分期规划

### MVP（P0）——「能记、能跟、能委派、管得住」

递归树模型 · 待办 + 计划 + 子计划 · 委派（含回执）· 重要程度三档与高优先级管控 ·
`doneAt` · 树形面板 + 筛选。

### V1（P1）——「AI 接管跟进」

agent 完成附证据 · 落后预警与逾期委派提醒 · 一句话周报/月报 · 周期复盘（agent 起草）·
面板就地编辑 · 委派验收。

### V2（P2）——「按需长出来」

看板视图 · 计划模板 · 委派给 agent 执行 · 统计报表。

## 8. MVP 验收标准（Definition of Done）

- [ ] 对话说一句「记一下，周五前把 XX 交给张三」，能自动建节点并挂到合理位置
- [ ] 计划可嵌套至少 5 层
- [ ] 「我委派出去的」视图能看到对象、期望完成时间、回执状态，逾期有标记
- [ ] 重要程度为「高」的节点缺周期/负责人时被拦下或警告
- [ ] 完成操作会写入 `doneAt`
- [ ] 面板与 agent 改的是同一份数据，且每次变更都留了快照
- [ ] 现有 54 个测试全绿，且新增测试覆盖新字段与新校验

## 9. 风险与假设

| 风险 | 影响 | 应对 |
|---|---|---|
| 委派是单方记录，同事不在这套系统里 | 「回执」只能靠手工更新 | 明确定位：回执由我方标记，不追求对方在系统内操作 |
| 递归树是破坏性变更 | 老 `plan.json` 需迁移 | 迁移机械可测；先做不破坏结构的字段加法 |
| 重要程度定不准（人会全标「高」） | 管控机制失效 | 默认「中」；只有「高」走重管控，保住区分度 |
| 需求随工作变化 | 模型反复改 | 字段全部可选 + 核心最小化，压低改动成本 |

**假设（待验证）**

- A1：确实是单人使用，无多人协同需求
- A2：周报是真实且高频的产出
- A3：委派对象是线下/微信里的人，系统只做记录与跟踪

## 10. 怎么判断做成了

| 指标 | 目标 |
|---|---|
| 计划覆盖率 | 本周实际做的事，80% 能在计划里找到 |
| 委派回执率 | 委派出去的事项中，回执状态明确的 > 90% |
| 周报生成耗时 | 从「回忆半小时」降到「一句话」 |
| 计划存活期 | 一个计划从建立到收尾 > 4 周（不烂尾） |

## 11. 待确认

1. **数据模型**：直接做递归树，还是先只加 `priority` / `delegate` / `doneAt` 三个字段？
2. **重要程度取值**：`high/normal/low` / A–C / 中文「高/中/低」？
3. **委派对象**：仅限「人」，还是也包括「交给 agent 执行」？
4. **周报产出物形式**：docx / 会话消息 / Markdown 文件？
5. **计划作用域**：只在当前工作区，还是跨项目共享一份？
